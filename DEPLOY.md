# Deploying: Neon + Render + Vercel

| Part | Service | What it hosts |
|---|---|---|
| Database | [Neon](https://neon.tech) | Postgres (keeps your data) |
| Backend | [Render](https://render.com) | FastAPI API |
| Frontend | [Vercel](https://vercel.com) | React site |

Do the steps in this order, because each step needs a URL from the one before.

## 1. Neon: create the database

1. Sign up at neon.tech (signing in with GitHub is easiest) and create a project.
   Turn on only **Postgres database**, and pick **AWS Asia Pacific 1 (Singapore)**, the same region
   `render.yaml` uses for the backend. Skip Neon's "set up with the Neon CLI" instructions; they
   aren't needed for this app.
2. On the project dashboard, copy the **connection string**. It looks like
   `postgresql://user:password@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require`
3. Keep it private: anyone with it can read and change your data.

The app creates its tables automatically on first start.

## 2. Render: deploy the backend

1. Sign up at render.com with GitHub.
2. Click **New → Blueprint** and choose the `eazyhall` repository. Render reads `render.yaml` from the repo.
3. It asks for the values marked `sync: false`:
   - `DATABASE_URL`: the Neon connection string from step 1
   - `ADMIN_PASSWORD`: a strong password for the first admin accounts
   - `CORS_ORIGINS`: leave as `*` for now; you'll fill this in at step 4
4. Click **Apply** and wait for the deploy to finish.
5. Copy the service URL, e.g. `https://eazyhall-api.onrender.com`. Opening
   `https://eazyhall-api.onrender.com/api/config` should show `{"demo_mode":false}`.

On first start the backend creates the two departments and their resources, plus one admin
per department: **`admin_computing`** and **`admin_athletics`**, both using `ADMIN_PASSWORD`.

> The free plan sleeps after a period with no traffic. The first request after that can take up to a minute.

## 3. Vercel: deploy the frontend

1. Sign up at vercel.com with GitHub.
2. Click **Add New → Project** and import the `eazyhall` repository.
3. Set **Root Directory** to `frontend`. Vercel detects Vite automatically.
4. Under **Environment Variables**, add:
   - `VITE_API_BASE` = `https://eazyhall-api.onrender.com/api` (your Render URL + `/api`)
5. Click **Deploy** and copy the site URL, e.g. `https://eazyhall.vercel.app`.

`VITE_API_BASE` is built into the site, so if you change it later, redeploy on Vercel.

## 4. Lock down CORS

In Render, open the service → **Environment**, set `CORS_ORIGINS` to your Vercel URL
(e.g. `https://eazyhall.vercel.app`, no trailing slash) and save. Render redeploys automatically.

## 5. Try it

Open the Vercel URL, choose a department, and sign in as `admin_computing` with your `ADMIN_PASSWORD`.
Students can create their own accounts with **Create Account**.

## Environment variables (backend)

| Variable | Production value |
|---|---|
| `DATABASE_URL` | Neon connection string |
| `SECRET_KEY` | Generated by Render. Keep it fixed, or everyone gets logged out. |
| `ADMIN_PASSWORD` | Password for the auto-created admin accounts |
| `CORS_ORIGINS` | Your Vercel URL |
| `DEMO_MODE` | `false`: no demo accounts, no tamper/heal tools |

Every push to `main` redeploys both Render and Vercel automatically.
